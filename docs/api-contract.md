# Shared app contract

All app JSON failures use `{error:{code,message}}`. Every mutation authenticates server-side. App requests use cookies and JSON; unsafe app methods verify Origin. In development allow http://localhost:5173 and http://127.0.0.1:5173. API keys use Bearer or x-api-key, separate from sessions.

## State
GET `/api/me` returns `{user,tree,rules,daily,providers}`. Anonymous user and tree are null; rules and providers are always present.
- user: `{id,username,displayName,role:'user'|'admin',status:'active'|'banned'|'deleted',coins,fertilizer}`.
- tree: `{seedClaimed:boolean,planted:boolean,height:number}`.
- rules: `{dailyFertilizer,inventoryLimit,coinsPerFeed,growthPerFeed,apiRateLimit}` nonnegative integers; growth and rate >0.
- daily: `{date,claimed,remaining}` (anonymous can be null). Asia/Shanghai date.
- providers: `{github:boolean,linuxdo:boolean}`; true only when the administrator enables that provider and both credentials exist. Login/register pages omit false providers entirely; existing bound identities remain visible on the account page.
POST `/api/auth/register` `{username,password,displayName?}`, `/api/auth/login` `{username,password}` return state; POST `/api/auth/logout` clears session.
GET `/api/auth/:provider/start` initiates login. Signed-in binding uses `?bind=1`; callback is `/api/auth/:provider/callback`. When requested through an origin different from `PUBLIC_ORIGIN`, start redirects to the configured origin before storing state or setting its Cookie. Successful callbacks redirect to the configured origin with `/?login=success` or `/account?bound=1`. Each successful third-party login synchronizes the site display name from the current provider nickname, falling back to the provider username; linking alone preserves the current site name. GET `/api/auth/identities` returns `{items:[{provider,providerUserId,displayName,createdAt}]}`; DELETE `/api/auth/identities/:provider` refuses removing last login method.

GET `/api/auth/oauth-landing?code=&state=` handles an authorization response unexpectedly returned to the homepage. A matching HttpOnly OAuth Cookie and an unexpired server state are required; the provider is looked up from that state, never selected from query input. The endpoint redirects to the controlled provider callback without consuming state, and the callback performs the normal one-time validation and token exchange. This compatibility path does not bypass a provider's configured `redirect_uri` checks. Browser navigation callback failures (`Sec-Fetch-Mode: navigate`) redirect to the configured homepage with a predefined actionable `error` message; messages exclude codes, state values, credentials, raw provider errors and URLs. JSON callback clients retain ordinary error status codes. All `/api/*` responses use `Cache-Control: no-store`; OAuth success and cached-page restoration trigger one state refresh without polling.

Callback diagnostics emit `oauth.callback.failed` or `oauth.callback.completed` with only controlled `{provider,stage,code}` values. They never include request headers/URLs, state, authorization code, cookies, Client ID/Secret or raw exceptions. Browser state-validation messages distinguish missing/mismatched cookies, expired/used states and changed configuration while preserving 400 `invalid_oauth_state` for JSON clients. A missing cookie explicitly asks users to start and finish authorization in the same browser; it does not weaken state validation or consume a matching pending server state.
POST `/api/tree/seed`, `/api/tree/plant`, `/api/tree/claim-fertilizer`, `/api/tree/feed` return refreshed state plus optional `{reward,tip,dialogue}`; all require `Idempotency-Key`. Plant/feed select a dialogue from the enabled model marked `isWisdomTree:true` in the same transaction. Its initial public ID is `wisdom-tree`; renaming it does not change the garden's model association. Feed reward is `{coins,growth}`, fertilizer claim reward is `{fertilizer}`. The server commits growth immediately; the client plays the complete original 31-frame/20-FPS pour before the 8-FPS visual growth animation. These are action responses, not polling endpoints.
POST `/api/tree/talk` requires an active signed-in user, a planted tree and `Idempotency-Key`; it returns a dialogue directly, without changing coins, fertilizer or tree height. A dialogue is `{modelId,modelDisplayName,replyId:string|null,content,index,total,fallback}`. `index` is the 1-based ordinal in the sorted pool, not the administrator's `position`; an empty pool returns the model default text with `replyId:null,index:0,total:0,fallback:true`. Garden dialogue has no customer input, so it uses the ordered pool rather than input rules. Replaying a game action returns its saved response and does not advance the dialogue sequence, including after a public model ID change. A disabled/deleted marked wisdom model makes new talk requests fail with 404 `model_not_found`; plant/feed still succeed without `tip` or `dialogue`.
GET `/api/models` returns `{items:[{id,displayName,coinsPerCall,enabled,isWisdomTree}]}` enabled models only.
GET `/api/keys` -> `{items:[{id,name,prefix,createdAt,lastUsedAt,revokedAt,key:string|null,recoverable:boolean}]}`; POST `{name}` -> `{key,item}`; DELETE `/api/keys/:id` revokes and clears ciphertext. New keys begin with `sk_`; the owning account can recover the complete value. Legacy digest-only and revoked keys have `key:null`. Key JSON responses use `Cache-Control:no-store`. Admin key metadata excludes the plaintext. `API_KEY_ENCRYPTION_KEY` is a persistent 64-character hex master key, required in production.
GET `/api/usage?page=1&pageSize=20` -> `{items,total}` request items `{id,modelId,coinsCharged,createdAt,endpoint,status}`.
GET `/api/ledger?page=1&pageSize=20` -> `{items,total}` ledger items `{id,kind,coinsDelta,fertilizerDelta,reason,createdAt}`.

## Admin

All admin routes require an active administrator session. Mutations accept an optional `reason` string; omission, an empty string or whitespace uses the audit explanation `管理员操作`. An explicit reason must be a non-whitespace string of at most 500 JavaScript characters. Admin forms do not require this field. DELETE bodies may be omitted; any supplied body must be a JSON object. Audit actor/action/before/after values and adjustment ledgers are still recorded. The last active administrator cannot be demoted, banned or deleted.

GET `/api/admin/stats` -> `{users,activeUsers,models,requests,coinsIssued,coinsSpent}`.

GET `/api/admin/oauth` -> `{items:[{provider:'github'|'linuxdo',enabled,available,clientId,hasClientSecret,callbackUrl,source:'database'|'environment'|'default'}]}`. Requires an active administrator and returns `Cache-Control: no-store`. `enabled` is the chosen switch; `available` also requires Client ID and Secret. Callback URLs are generated from `PUBLIC_ORIGIN` as `/api/auth/<provider>/callback`. Client Secret, ciphertext, fingerprint and encryption key are never returned.

PATCH `/api/admin/oauth/:provider` accepts `{enabled?,clientId?,clientSecret?,clearSecret?}` and returns `{item}` with the same metadata. Booleans must be boolean. Client ID permits at most 512 JavaScript characters and is trimmed; Client Secret permits at most 4096. Omitting a Secret or supplying blank/whitespace preserves the current Secret. `clearSecret:true` explicitly removes it; a simultaneous nonblank replacement is invalid. Enabling without both credentials, or clearing a Secret while leaving the provider enabled, returns 400 `oauth_credentials_required` with no saved changes. An unknown provider returns 404. Changed settings are audited as `oauth.update` with sanitized before/after metadata and reason `管理员操作`; audit never contains Secret or ciphertext.

Secrets are stored as AES-256-GCM ciphertext under `API_KEY_ENCRYPTION_KEY` with an OAuth/provider-specific authentication context. Preserve this master key with database backups. Untouched settings retain compatibility with existing environment Client IDs/Secrets; both configured credentials enable that legacy provider. No credentials means default disabled. The first explicit administrator configuration creates a complete database override, including encrypted retention of any existing environment Secret. Later environment changes cannot override this saved switch or credentials. Blank Secret-only / empty-body updates are no-ops.

Updates apply without restarting and invalidate outstanding authorization states for that provider. OAuth start/callback enforce availability server-side; disabled providers return 503 `provider_unavailable`. Each state records a configuration fingerprint. After provider network requests finish, the identity-acceptance transaction acquires a shared configuration lock and rechecks availability/fingerprint, preventing changed/disabled configurations from completing an old authorization. Network I/O holds no database lock. Disabled/changed providers do not delete existing identity bindings or revoke accepted login sessions.
GET `/api/admin/users?search=&page=1&pageSize=20` -> `{items,total}`; each item extends the public user with `identities:[{provider,providerUserId,displayName,createdAt}]`. Identity metadata for the current page is fetched in a single batch; no identities are returned for unrelated users. POST `{username,password,displayName?,role?,reason?}` creates local user.
GET `/api/admin/users/:id` -> `{user,tree,identities,keys,usage,ledger}`. Identities have the same four-field metadata shape as the listing; third-party access tokens and Client Secrets are never stored in or returned as identity metadata. PATCH `{username?,displayName?,role?,status?,reason?}`. DELETE with optional `{reason?}` soft-deletes.
POST `/api/admin/users/:id/password` `{password,reason?}` resets and invalidates sessions. POST `/api/admin/users/:id/adjust` `{coinsDelta?,fertilizerDelta?,reason?}` requires at least one nonzero adjustment.

GET `/api/admin/models` -> `{items,defaultReplyText}` including disabled, excluding deleted. `defaultReplyText` is the public seed text for the new-model form. Each admin model is `{id,displayName,coinsPerCall,enabled,isWisdomTree,replyText,streamChunkChars,streamDelayMs,replyCount,ruleCount}`. Counts include all live numbered replies and all input rules, including disabled rules. `isWisdomTree` is a server-maintained identity marker, not an editable request field.

POST `/api/admin/models` `{id,displayName,coinsPerCall,replyText?,enabled?,streamChunkChars?,streamDelayMs?,reason?}` -> `{model}`. Omitting `replyText` uses the public ASCII egg seed; explicit text remains editable. PATCH `/api/admin/models/:id` accepts any subset of these fields -> `{model}`, preserving existing text when omitted. IDs are 1–128 JavaScript characters, begin with an ASCII letter or digit and otherwise contain ASCII letters, digits, `.`, `:`, `_` or `-`. All existing models, including the marked wisdom model and models with prior calls, may change ID. A duplicate ID, including a soft-deleted model's ID, returns 409 `model_id_exists` on rename. The change atomically cascades to request associations, reply pools, input rules and per-user cursors; stored response snapshots, original request hashes and existing audit/ledger text remain unchanged. Consequently usage associations show the new ID, while a same-key replay using the exact original request body still returns the old response and old response model ID. New requests must use the current ID; there is no old-ID alias. Changing the model field of a replay body instead returns 409 `idempotency_conflict`.

Model coins per call are integers 0–1,000,000; `enabled` is boolean. Stream chunk size is an integer 1–1,000 (default 8); delay is an integer 0–1,000 milliseconds (default 20). Default text, every numbered reply and every rule output must satisfy the text and stream-duration constraints below, even for disabled rules. DELETE `/api/admin/models/:id` with optional `{reason?}` soft-deletes. A new model starts with one reply numbered 1. Changing `replyText` updates that initial reply only while it remains the sole entry and still equals the old default text; independently configured reply pools are preserved.

GET `/api/admin/models/:id/replies` -> `{items:[{id,position,text}],total}`, ordered by `position,id`, for an existing non-deleted model, including disabled models.
POST `/api/admin/models/:id/replies` `{position,text,reason?}` -> `{item}`. PATCH `/api/admin/models/:id/replies/:replyId` `{position?,text?,reason?}` -> `{item}`. DELETE the same reply path with optional `{reason?}` -> `{ok:true}`. Positions are unique positive integers up to 1,000,000 per model (duplicate returns 409 `reply_position_exists`); each model permits at most 500 entries (409 `reply_limit`). Text must contain non-whitespace content and be at most 20,000 JavaScript characters; leading/trailing output whitespace is preserved. Configured stream duration `ceil(Array.from(text).length / streamChunkChars) * streamDelayMs` must not exceed 120,000 milliseconds. These changes write before/after values to the audit log. Reply deletion removes the live entry, while accepted request snapshots remain intact.

GET `/api/admin/models/:id/rules` -> `{items:[{id,position,input,text,enabled}],total}`, ordered by `position,id`, for an existing non-deleted model, including disabled models.
POST `/api/admin/models/:id/rules` `{position,input,text,enabled?,reason?}` -> `{item}`; `enabled` defaults to true. PATCH `/api/admin/models/:id/rules/:ruleId` `{position?,input?,text?,enabled?,reason?}` -> `{item}`. DELETE the same rule path with optional `{reason?}` -> `{ok:true}`. Rule/reply IDs are UUIDs. Rule positions are integers 1–1,000,000, unique within that model's rules (409 `rule_position_exists`); they are independent of reply positions. Each model permits at most 500 rules (409 `rule_limit`), counting disabled rules. `input` must contain non-whitespace text and have original JSON string length at most 2,000 JavaScript characters; it is stored with outer whitespace trimmed. Output `text` has the same 20,000-character and 120-second constraints as numbered replies. `enabled` must be boolean. Duplicate input text is allowed; matching picks the enabled rule with the smallest position. Rules are independent for each model and their changes are audited. Editing, disabling or deleting a rule affects new calls only, leaving accepted replay snapshots intact.

Example rule create body: `{"position":1,"input":"你好","text":"你好","enabled":true}`. No operation reason is needed.

GET `/api/admin/settings` -> rules; PATCH same rule keys plus optional `{reason?}` returns rules.
GET `/api/admin/audit?page=1&pageSize=20` -> `{items,total}` items `{id,actorId,actorName,action,targetId,reason,before,after,createdAt}`.
GET `/api/admin/usage?page=1&pageSize=20&userId=&modelId=` -> `{items,total}` including username.

## Simulator
`/v1/models`, `/v1/chat/completions`, `/v1/completions`, `/v1/responses`, `/responses`, `/v1/messages`, `/v1/messages/count_tokens`, `/health`. Official text JSON/SSE shapes. Generation accepts declared history/tools but only returns configured text. Model ID must exist and be enabled. Usage token values are estimates, never used for coin charging. Models/token-count/health free. Optional Idempotency-Key scoped to user and canonical endpoint: hash request, same key different request 409, replay saved output/price; user/key still must be active. Acceptance transaction conditionally debits coins, inserts usage/ledger/result snapshot. All pre-acceptance failures are free; acceptance commits before sending success. Disconnect after acceptance remains charged once. Stop stream timers on close. Do not store prompts in normal request logs.

Generation selects a configured response in this order: enabled exact input rule → next numbered reply → model default when the reply pool is empty. Matching trims outer whitespace and preserves case and internal whitespace; it is not substring, regular-expression or semantic matching. Only the latest user-authored text is considered; an earlier matching user message cannot override a later unmatched one. System, assistant, tool and image content are excluded.

| Protocol | Rule input |
| --- | --- |
| Chat Completions / Anthropic Messages | Last `role:"user"` message's string content, or its `type:"text"` blocks joined without separators |
| Responses | String `input`, or the last `role:"user"` item's string content / `type:"input_text"` blocks joined without separators |
| Completions | String `prompt`, or the first prompt when passed a batch of strings; token-array prompts do not match input rules |

A matched rule does not create or advance the numbered-reply cursor, but the call still undergoes ordinary authentication, model-state, rate-limit and coin checks and is charged by the model price. JSON and SSE use the same selection. The saved internal receipt includes `ruleId` for a rule hit, with `replyId:null,replyIndex:0,replyTotal:0`; it preserves that selected text and stream parameters even if the rule later changes or disappears.

For unmatched calls, each model cycles through its own reply pool by ascending position. One cursor per user/model is shared across all generation protocols; the marked wisdom model also shares that cursor with garden plant/feed/talk, including after an ID rename. Garden actions have no input and always use the ordered pool or empty-pool default. Different users and models remain independent. The user row lock serializes cursor selection and billing; a shared model lock prevents live reply changes during selection. The saved result includes the selected reply text, ID, ordinal, total and stream parameters; the request row also stores its accepted coin charge. Replay does not choose another reply or advance the cursor. If the last selected live reply is deleted, the next selection starts from the first current entry. New databases seed `wisdom-tree` (display name 智慧树, 1 coin/call) with 80 Chinese gameplay summaries and original chats covering all 80 original numeric source keys. Source height metadata is audit-only and does not filter the demo pool; see `docs/wisdom-corpus.md`. The upgrade corrects the untouched legacy default placeholder to the first imported reply without replacing administrator edits or re-importing the pool.
# 网站更新

- `GET /api/system/update` 免费返回运行提交、仓库最新提交、`phase`、更新能力和安全的 Actions 进度链接。`canUpdate` 表示凭据已配置，POST 仍单独检查当前管理员权限。GitHub 查询全局缓存、并发合并，没有后台定时查询；错误和未知版本不能显示为最新。
- `GET /api/admin/update/settings` 返回 `{ enabled, tokenConfigured, repositoryUrl, branch }`；`PATCH` 接受 `{ enabled, token?, clearToken? }`，留空保留、清除前关闭，返回同一脱敏结构。凭据加密存储，不在审计或响应中出现。
- `POST /api/admin/update` 接受 `{ expectedVersion }`，只触发受配置仓库的 `cd.yml`，附带本站域名、目标提交和请求 ID。工作流先检查目标，测试通过后按现有备份与回滚流程部署。重复或并发请求共用单个正在执行的更新；提交响应丢失时保留待确认状态，不能假定失败后重复提交。
